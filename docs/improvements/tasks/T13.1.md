## 1. The failure

CI log (`ci-job.log`, line 3209): `FAIL short-notes held min: until the note-off the short note renders as the uncut note (max |diff| <= 0.0002 of the peak) (q0 126 @0.0700 s: 1.47e+0)`.

- One program (126, Applause, quality 0), one duration, one build. The other 1,023 renders of that case, and the same case on `source`, were within 1.7e-5.
- 1.47 of the peak is not a tolerance miss. It is a whole segment of one render that differs from an otherwise identical render.
- PR #60 does not touch the engine or the spec, and the case passed on re-run.

## 2. Cause

This is WebKit's occasional non-reproducible render difference, known since T6 (`tasks/T6.md` §4.2 and "WebKit's occasional render differences": one changed segment of up to 0.56, about 1 in 12,000 renders, cause not isolated, never seen in Chromium or Firefox). `specs/render.js` and the `completed` case of this spec already re-render and reconcile it. The `held` case compares a short note to the uncut note and had no such step, and it makes the most renders in the spec (1,024 renders per build).

Reproduced locally (WebKit, `--engines=webkit --specs=short-notes`, the unmodified spec, 12 runs, logs `base-*.log`):

| Run | What happened |
| --- | --- |
| 2 | `held source` failed: `q0 127 @0.0700 s: 1.83e+0` (a different program and build: not a deterministic defect) |
| 4 | `completed source` reconciled q0 program 126 (first diff 0.547) |
| 10 | `completed min` reconciled q0 program 122 (first diff 0.438) |

Three glitches in 12 runs (about one in four), one of which landed in `held` and failed it (one failure in 12 runs; the CI failure is one in an unknown number). The `completed` ones were absorbed by its existing reconciliation. A reproducible engine defect would fail the same program and duration every time. These moved between programs, durations and builds, so this is the known WebKit effect and not an engine bug.

## 3. Fix

The standard technique of T6 §16 (`specs/render.js`, and `completed` here), applied to `held`:

- A (program, quality, duration) item outside either bound, the audibility floor (`hold >= audiblePeak`) or the follow bound (`|diff| <= FOLLOW` of the peak), is re-rendered (the short note and the uncut note, alone), at most twice. It passes only if a re-render is inside both bounds. It fails with the first result otherwise.
- At most `MAX_RECONCILE` (3, as in `render.js`) items per case are re-rendered, so a frequent difference fails.
- Every reconciled item is recorded: observation "reconciled held renders" with the quality, program, duration, the first hold and first relative difference, and the render count.

No tolerance was loosened: `FOLLOW`, `audiblePeak` and `sameEngineSample` are unchanged. A measured WebKit variance cannot justify a wider `FOLLOW`, because the glitch is not small noise (1.47 and 1.83 of the peak, against 1.7e-5 normally).

Not wrapped: the release-level, zero-length and preroll cases make fewer than 30 renders each, against about 2,000 for the rest of the spec, and the preroll case compares two renders of one note exactly.

## 4. Why the check keeps its teeth

A defect of the library is a function of the inputs, so the same calls give the same difference on every re-render. The re-renders fail and the check fails with the first result.

Pre-fix engine (`_evidence/t13-short-notes/vacuity/prefix`: upstream's `t2` and release, with the same test spec as this branch; terminating renders only, CONCURRENCY rule 10):

| Engine | Result |
| --- | --- |
| WebKit | 2 of 8 cases pass; both `held` checks fail on `source` and `min` (silent while held at 0.025 s from q0 program 23 on, as T6 §18.5 measured); "reconciled held renders" = `[]` |
| Chromium | 2 of 8 pass; `held` fails 4 of 4 (source, min, both checks); `[]` |
| Firefox | 4 of 8 pass; `held` fails 4 of 4; `[]` |

The re-render path itself was exercised on the fixed build with a glitch injected into one render (a scratch copy in `_evidence/t13-1-flake/inject`: 0.5 added to 128 samples of the first short-note render of q0 program 126, WebKit). Result: reconciled once, in 2 renders, recorded as `{"q":0,"program":126,"D":0.025,"hold":0.512,"rel":30.5,"renders":2}`, all 8 cases pass.
