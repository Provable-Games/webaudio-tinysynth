# P1-A2: Browser release gate integrity (#79)

## Scope and behavior

This change strengthens the existing browser matrix aggregate. The aggregate compares each downloaded shard with an independently expected GitHub run context, the checked-out source and fresh minified build hashes, the matrix-configuration fingerprint, the resolved Playwright Core package and `browsers.json` hash, and exact engine/shard/step/spec/case membership. Each engine result also binds the revision directory declared by that manifest; the aggregate resolves the same package independently under the active `PLAYWRIGHT_CORE` override and checks the exact engine bundle. Browser-reported version alone is insufficient because different WebKit revisions can both report 26.6. The gate rejects malformed worker diagnostics, failure states, missing or duplicate evidence, absent measurements, JSON `null` where a number is required, and invalid generated-buffer hashes before exposing cross-engine comparisons.

The new `full-mix` spec is deliberately fixture-scoped. It renders the pinned TinyChip consumer regression fixture and the repository's synthetic `ws.mid` q1 profile at quality 1 and 44.1/48 kHz. Both raw stereo channels remain Float32 until finiteness and full-scale checks complete. The independent MIDI decoder determines expected note-on identities and timing; the browser instrumentation counts actual native note/source creation and early pruning. Mixed overlapping note windows are labeled as features of the summed bus, not proof that each voice is audible. Two documented fixture timbres are probed after the song and its reverb tail through the same output graph, on two distinct channels checked against every channel message in the fixture MIDI. The probes have independent program/tuning state and no channel-wide cleanup message can stop the other scheduled probe. Relative probe level is an isolated-timbre check, not a musical-part balance claim.

The isolated pitch probe searches broadly around the timbre-derived intended note, then applies a separate 35-cent normative bound. The bound is one third of a semitone: it is well below the 100-cent wrong-semitone fault, while allowing for small oscillator/table/FM estimator offsets. TinyChip program 0 and 20 are probed with their pinned carrier-derived pitch. The ws.mid q1 program 37 two-operator bass sample measured only -21.5 dB fitted-tone fraction in the first native capture and is not treated as a pitch-qualified timbre; the fixture uses its measured program 81 patch at C4 and A4 instead. No confidence threshold was relaxed. The 180 ms analysis segment contains about 40 cycles at the lowest probe fundamental (A3, 220 Hz) and 79 at A4. Its unpadded Fourier-bin spacing is 5.56 Hz at 44.1 kHz or 6.25 Hz at 48 kHz; Blackman-Harris windowing, at least 8x zero padding and log-peak interpolation refine the peak estimate, with sub-cent error measured on the known-tone Node signal fixtures. The 35-cent choice is therefore a patch and defect-separation policy, not the raw-bin resolution. The fitted intended-frequency component must be at least -12 dB relative to segment RMS, allowing harmonic-rich waveforms while rejecting broadband synthetic noise (about -32 dB); the selected peak must be at least -36 dB relative to the strongest spectral bin. These analyzer-fault checks use synthetic Float32 signals. Native browser captures are recorded separately below and do not imply physical-device evidence.

The mixed-bus downbeat metric in `fullmix-feature-v6` is a fixed-frequency band projection, not a pitch estimator. Independent MIDI decoding selects the note ID and key. For the TinyChip fixture, pinned program 20 has a primary oscillator ratio `t=0.5`, so MIDI 45 maps to carrier MIDI 33 (55 Hz). For the q1 `ws.mid` fixture, pinned program 37 has a primary triangle ratio `t=2`, so MIDI 30 maps to carrier MIDI 42 (92.4986 Hz). The analyzer projects the two actual mixed-bus channels at that expected frequency; the resulting level is a per-engine reference band feature only. It cannot prove the downbeat voice itself played at that pitch inside an overlap. Isolated post-song probes carry the normative pitch checks.

Each first attempt controls eligibility. Repeats are retained as diagnostics and cannot promote, replace or fail an otherwise passing first attempt. The aggregate re-hashes and re-measures raw WAV artifacts and requires the exact frame count `ceil(renderDurationSec * sampleRate)`, exact byte size, RIFF/data lengths, sample rate, byte rate, block alignment, two IEEE Float32 channels, per-channel hashes, and the planar-channel PCM hash. It checks raw PCM before encoding and checks the first attempt for non-finite and over-full-scale samples. Diagnostic audio defects remain visible without changing attempt 1's verdict.

The `render` spec also retains both original Float32 WAVs for a failed first-attempt comparison before diagnostic rerenders begin. Retention is bounded to six comparison pairs per case, recorded with the two roles, dimensions, and byte hashes under `first-attempt-pcm/q<quality>-<sampleRate>/`; ordinary Browser Matrix shard uploads include these files. This preserves first evidence without changing the comparison verdict, rerender budget, or tolerance. Local runs without `--out` continue to run without sidecar retention; strict CI artifact validation remains unchanged.

Run and report hashes detect stale or misidentified downloaded reports, but report metadata is not cryptographic attestation. Pull-request workflow scripts are supplied by the pull request. This gate does not create a protected producer boundary or change repository settings. Requiring the check on `main` and enforcing current-base/freshness rules remain user-administered release controls.

## Qualification limits

The repository does not contain the unfinished Casey production source/setup pair. `tinychip-ws-mid` uses an older pinned consumer fixture export and explicitly records that its conversion is not current player wire bytes. `ws-mid-default` is a synthetic profile. These captures can exercise the gate but cannot qualify a production pair or establish composer approval. Patch-aware isolated probes do not certify musical-part balance. Physical phones, tablets and other hardware remain untested. Production-pair certification is owned by the separate A3 track.
