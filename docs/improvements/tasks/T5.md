## 2. Numeric contracts (#13, D-013)

One rule for every numeric argument: a **number**, or a **non-blank numeric string** read with `Number()`; the result must be **finite** and **in range**, and an **integer** where it indexes a table. The converted number is what the synth stores. A value that is not a number or such a string (`undefined` or `null` where the argument is required, booleans, objects, `""`, `"  "`) throws a `TypeError`; a number or numeric string that is NaN, ±Infinity, out of range or not an integer where one is required throws a `RangeError`. The message starts with the argument's name (`channel out of range: 16`, `velocity is not a number`).

Every method checks all its arguments **before** anything changes: no state, no WebAudio call, and no lazy context (validation runs before T4's `_live()` guard, so a bad call on a `lazy: true` synth creates no context). After `dispose()` a valid call is still T4's no-op, and a bad call still throws: misuse is reported whatever the lifecycle state (a deliberate reading of D-018's "safe no-ops", which concerns calls that are valid).

| Argument | Methods | Range | Integer | Optional |
| --- | --- | --- | --- | --- |
| channel | `noteOn`, `noteOff`, `setProgram`, `setBendRange`, `setBend`, `setModulation`, `setChVol`, `setPan`, `setExpression`, `setSustain`, `allSoundOff`, `resetAllControllers` | 0–15 | yes | no |
| note | `noteOn`, `noteOff` | 0–127 | yes | no |
| velocity | `noteOn` (0 is a note-off, as before) | 0–127 | no | no |
| program | `setProgram`; `setTimbre`/`getTimbreName` with `m` 0 | 0–127 | yes | no |
| drum note | `setTimbre`/`getTimbreName` with `m` 1 | 35–81 | yes | no |
| `m` | `setTimbre`, `getTimbreName` | 0–1 | yes | no |
| controller value | `setModulation`, `setChVol`, `setPan`, `setExpression`, `setSustain` | 0–127 | no | no |
| bend | `setBend` (8192 centre) | 0–16383 | no | no |
| bend range | `setBendRange` (14-bit, semitones·128 + cents) | 0–16383 | no | no |
| time `t` | `noteOn`, `noteOff`, `setBend`, the five controller setters, `send` | ≥ 0, finite | no | yes: `undefined`, `null` and 0 mean now |
| `quality` | `setQuality`, constructor option | 0–1 | yes | yes: `setQuality()` reapplies the current quality |
| `voices` | `setVoices`, constructor option | 1–4,294,967,295 | yes | no |
| `loopEnd` | `setLoopEnd` | ≥ 0, finite (whole ticks, D-019 F8) | yes | no |
| `masterVol`, `reverbLev` | `setMasterVol`, `setReverbLev` | ≥ 0, finite | no | yes: no argument reapplies the current value |

Why these choices:
- **Indices integer, levels real.** Channel, note, program, drum note and `m` index arrays or tables; a fractional value reached `undefined` (`program[5.5]`) or NaN (`scaleTuning[ch][60.5 % 12]`). Velocities, controller values and bends scale parameters, so a slider's fractional value keeps working.
- **No upper bound for times, `masterVol` and `reverbLev`** beyond finiteness (D-028, "check format, not cost"): a gain above the default is legitimate. **`voices`' bound** is 2³²−1, the largest array length: it is the documented upper bound the assignment asks for, and it is a natural limit, not a throttle (offline renders need `voices` ≥ the note count, T4 §4).
- **`null` for optional arguments** keeps the legacy `t == undefined` and `v != undefined` checks: `null` and `undefined` behave alike, as before.
- `setLoop`, `setTsMode`, `locateMIDI` and `useReverb` are unchanged (not in #13's list; `locateMIDI` is T3's transport and tolerates any tick).

## 3. Raw messages through `send()` (#13)

`send(msg, t)` checks `t` as above and requires `msg` to be an object (an array or typed array); otherwise it throws `TypeError: msg is not an array`. Everything else malformed is a **no-op**, decided before `_live()`, `resume()` or any state:
- the status byte `msg[0]` is not an integer number 0x80–0xFF;
- the message is shorter than its status needs: 3 bytes for 0x8n, 0x9n, 0xAn, 0xBn, 0xEn; 2 for 0xCn, 0xDn; 1 for 0xF1–0xFF; a SysEx (0xF0) uses all its bytes;
- one of those data bytes is not an integer number 0–127, except that a SysEx may end with 0xF7.

Unknown but well-formed messages (aftertouch, system common) stay no-ops, as before. A well-formed message reaches the setters with valid numbers, so `send()` never throws after its checks. Upstream turned `send([0x90, 60])` into a note with a NaN gain and `send([0xb0, 7])` into a NaN channel volume (§6); both now do nothing. SMF files cannot produce malformed channel messages (T2's parser checks data bytes); an F7-escape event carrying bytes ≥ 0x80 is now ignored by `send()`, which matched no handler before either.

## 4. Timbres (#13, ledger L-09)

`setTimbre(m, n, p)`: `m`/`n` as in §2, then `p` must be a non-empty `Array` (`TypeError: timbre is not a non-empty array`), and each operator (`_op`) must be a non-null object. Each operator is **copied** (`Object.assign({}, o)`), missing or `undefined` fields take the defaults `{g:0, w:"sine", t:1, f:0, v:0.5, a:0, h:0.01, d:0.01, s:0, r:0.05, p:1, q:1, k:0}` (appended in that order, exactly as upstream filled them), and the copy is checked:

| Field | Contract | Reason |
| --- | --- | --- |
| `w` | `"sine"`, `"square"`, `"sawtooth"`, `"triangle"`, `"w9999"`, `"n0"` or `"n1"` (T11 adds registered names) | anything else threw in `_note` (`w…`, `n…`) or played a sine silently |
| `g` (operator `i`, 0-based) | integer 0 (output), 1–min(i, 10) (FM into operator g−1) or 11–10+i (AM into operator g−11) | `_note` reads the target operator, which must already exist (D-010 Q12) |
| `a`, `h`, `d`, `r`, `q` | finite, ≥ 0 | times and Web Audio time constants (negative ones throw a `RangeError` in `setTargetAtTime`) |
| `t`, `f`, `v`, `s`, `p`, `k` | finite (any sign) | built-ins use `f` −2 and `k` −1.2; negative ratios, levels and gains are valid Web Audio values (D-028) |

Numeric fields follow §2's rule (numeric strings become numbers in the copy). Messages name the operator and field (`operator 1 g: 2 is not an earlier operator`, `operator 0 w: unknown wave saw`). The array is built with `Array.from`, so a hole is an operator `undefined` (rejected). **Transactional:** every operator is checked and copied before the one assignment `program[n].p = copy` (or `drummap[n−35].p`), so a rejection leaves the slot as it was. **Ownership:** the caller's array and objects are never modified (frozen timbres now work; upstream threw on them in strict mode), and later caller edits do not reach the synth. `setQuality()` installs the built-in tables through the same path, so the built-in tables `program0`, `program1`, `drummap0` and `drummap1` are no longer filled in place or aliased by `program[n].p`.

**Out-of-range slots** throw instead of doing nothing, and an `m` other than 0/1 is rejected (upstream treated any truthy `m` as a drum).

**Computed values** (FM chains or a large `k` producing a non-finite AudioParam value) are not guarded here: that is T5.2 (D-030); `_note` is untouched.

### Editor decision (D-011 item 3)

- **Unknown keys are accepted, copied and ignored.** `b` and `c` (built-ins and the editor's placeholder) and any other key survive in the installed copy, so `JSON.stringify(program[n].p)`, the text soundedit's `ViewDef()` shows, is byte-identical to upstream's for every built-in in both qualities (unit test against upstream itself), and an edited patch round-trips with the same keys in the same order. Copying unknown keys also lets T12's `fl`/`ff`/`fq`/`fk` pass through unchanged once its check is folded in.
- **The editor's placeholder operator** `{g:0, w:"sine", v:0, t:0, f:0, a:0, h:0, d:1, s:0, r:1, b:0, c:0, p:1, q:1, k:0}` is valid (zero level, zero ratio and zero times are in range).
- **Re-applying after `setQuality()`:** `setQuality()` reinstalls the built-ins, as before. An editor that keeps its patch (for example the JSON it shows) calls `setTimbre(m, n, patch)` again; the unit round-trip test shows the reinstalled patch and the next note's WebAudio calls are identical to the first application.
- **Today's soundedit** edits `synth.program[n].p` in place (T9A E6) and never calls `setTimbre`. That still changes the sound, because it edits the installed copy, but it no longer changes the built-in tables (E6's aliasing is gone), and it bypasses validation. T9-8 moves the editor to `setTimbre` (build a fresh array from the form, call `setTimbre`, show errors, reapply after a quality change).

## 5. URL loading (#14, ledger L-10)

`loadMIDIUrl(url, opts)` returns a promise. It still uses `XMLHttpRequest` (`GET`, `responseType` `"arraybuffer"`), so the classic script needs nothing new, and inline embedding (which never loads URLs) is unaffected.

- **Resolves** with the response's `ArrayBuffer` once `loadMIDI()` has installed it (the exact bytes that were installed; callers can keep or hash them).
- **Rejects**, leaving the song, playback and channel state as they were:

| Reason | Rejection |
| --- | --- |
| `url` missing (`undefined`, `null`, `""`) | `TypeError("url")`, no request |
| `opts.signal` is not an `AbortSignal` | the `TypeError` from `addEventListener`, before anything is registered or superseded; no request is sent |
| the synth is disposed, or `dispose()` runs while the load is pending | `Error`, `code`/`message` `SYNTH_DISPOSED` (as `resume()`) |
| `opts.signal` aborts (or was already aborted: no request) | `signal.reason` (an `AbortError` `DOMException`, or the caller's reason), as `fetch` does |
| a newer `loadMIDIUrl()` starts, or a direct `loadMIDI()` installs a song first | `Error`, code `LOAD_SUPERSEDED` |
| status outside 200–299 (`fetch`'s `ok`); `status` 0 included | `Error`, code `HTTP_STATUS`, with `status` |
| network failure (connection refused or reset, CORS) or a browser-aborted request | `Error`, code `NETWORK_ERROR` |
| the body does not parse (empty 204, non-MIDI, truncated) | `loadMIDI()`'s error (`SMF_*` code, `offset`, `track`) |

- **Non-200 policy:** any 2xx installs its body if it parses; a 204 has no body and so rejects `SMF_INVALID_HEADER`; redirects are followed by the browser (the final status counts).
- **Never throws:** every failure, including `open()` throwing for a malformed URL, is a rejection.
- **Fire-and-forget:** the returned promise has its own rejection handler, so ignoring the result causes no unhandled rejection. A caller who chains `.then(f)` owns that new promise and must handle its rejection, as with any promise.
- **Stale responses:** a newer call rejects the older one at once and aborts its request; a direct `loadMIDI()` that installs a song while a request is pending makes its response stale (detected by song identity at response time, so the parser is untouched). A direct load that fails changes nothing (D-013) and so does not supersede. A newer call that never starts (missing url, aborted signal, `open()` throwing) leaves the older load alone.
- **Dispose:** the load registers a canceller in T4's `_pend` set. `dispose()` calls it: the promise rejects `SYNTH_DISPOSED` at once and the response, when it arrives, is discarded without calling `loadMIDI`. The request itself is **not aborted** on dispose (it is for a newer call or the signal). Reason: T4's browser dispose spec (`tests/browser/specs/dispose.js`, "a URL load pending at dispose(): its response arrived", `r.done.status === 200`) asserts that the response still arrives; aborting would fail it, and that spec is outside T5's files. The supervisor decided to keep this behavior (it matches #14's "abort/invalidate"); T4's dispose spec is unchanged.
- **`loadMIDIfromSrc()`** returns the same promise (`TypeError` when `src` is unset, as a missing url).
- **Lazy synths:** the request does not create the context; installing the response does (`loadMIDI` is a first use, T4).

## 8. Conflict with T3's scheduler test (resolved: the supervisor approved the diff)

## 13. Draft README/NOTICE text (CONCURRENCY rule 4; the supervisor adds it)

**README, "What behaves differently":**
- Public functions check their arguments before changing anything. Channels are 0–15; notes, programs, velocities and controller values 0–127; bends and bend ranges 0–16383; times finite and ≥ 0 (or omitted); `setQuality` 0 or 1; `setVoices` a whole number ≥ 1; `setLoopEnd` whole ticks ≥ 0; volumes and reverb levels ≥ 0. Numeric strings such as `"64"` are accepted. Anything else throws a `TypeError` or `RangeError` and changes nothing; `setQuality("0")` now selects quality 0 (upstream selected 1), and an out-of-range `setTimbre` slot throws instead of being ignored. A malformed raw message passed to `send()` (too short, or a data byte above 127) is ignored.
- `setTimbre()` checks the timbre (known waveform, routing only into an earlier operator, finite values, times ≥ 0) and stores a copy with the defaults filled in: your objects are no longer modified, and the built-in tables are no longer changed by edits to the installed timbre.
- `loadMIDIUrl()` returns a promise and accepts `{signal}` to cancel. It resolves once the song is installed and rejects with a coded error otherwise; a newer load or a direct `loadMIDI()` wins over a pending one; `dispose()` cancels it. Ignoring the result never leaves an unhandled rejection.

**README, function entries:**
- `setQuality(q)`: add "`q` is 0 or 1 (a numeric string is accepted). Reinstalls the built-in timbres, so custom timbres must be set again afterwards."
- `setTimbre(m,n,p)`: replace "(Details are not yet documented)" with the §4 contract and "`p` is copied; unknown keys are kept and ignored; the call throws and changes nothing if `p` is invalid."
- `loadMIDIUrl(url, opts)`:
  > Loads a Standard MIDI File from `url` and returns a promise that resolves with the response's `ArrayBuffer` once the song is installed. It rejects, leaving the current song, with an `Error` whose `code` is `HTTP_STATUS` (with `status`; statuses 200–299 succeed), `NETWORK_ERROR`, `LOAD_SUPERSEDED` (a newer `loadMIDIUrl()` or a direct `loadMIDI()` came first), `SYNTH_DISPOSED`, or an `SMF_*` code from `loadMIDI()`; with `opts.signal`'s reason when that `AbortSignal` aborts; or with a `TypeError` for a missing `url`. It never throws. Fire and forget is safe: `synth.loadMIDIUrl("song.mid")` leaves no unhandled rejection. To show errors: `synth.loadMIDIUrl(url).then(() => synth.playMIDI(), (e) => show(e.code || e.name))`.
- `send([midi-message], t)`: add "A message that is too short for its status byte, or has a data byte that is not 0–127, is ignored. `t` must be omitted, 0 or a finite time ≥ 0."

**NOTICE bullet:**
  - webaudio-tinysynth.js: public functions validate their arguments and
    timbres before changing anything (TypeError/RangeError), setTimbre()
    stores a validated copy instead of modifying the caller's objects,
    malformed raw MIDI messages are ignored, and loadMIDIUrl() returns a
    cancellable promise that rejects on HTTP, network and parse errors
    and ignores stale responses.
