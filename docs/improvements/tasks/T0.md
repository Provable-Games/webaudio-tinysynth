## 6. Public surface inventory

The full data is in `probe-results/inventory.json`. The source and min builds agree on every hash and on the method and property lists.

- **Exports.**

| Path | Behavior |
| --- | --- |
| Classic script | `window.WebAudioTinySynth` (the IIFE receives `this`) |
| AMD | `define(factory)` is called once and returns the class, with no global set |
| CommonJS | `module.exports = WebAudioTinySynth`, with no global leak. `window` is bound to the original `module.exports` object, so `init()` resolves `AudioContext` from the global scope. |
| Top-level `this` undefined (native ESM) | Without `module`, loading throws `Cannot set properties of undefined (setting 'WebAudioTinySynth')`. With `module`/`exports`, loading succeeds but construction throws `Cannot read properties of undefined (reading 'AudioContext')`. |

- **Constructor options:** `quality`, `useReverb` and `voices` only. The constructor runs `setQuality(1)` first, then applies the options, then calls `init()`. `internalcontext` has no option, so the constructor always creates an AudioContext. It then plays a velocity-1 warm-up note (60), which stays in `notetab`. It also starts one 60 ms interval that is never cleared. Nodes created by the constructor: 36 gains, 16 stereo panners, 3 oscillators (LFO and warm-up), 1 compressor, 1 convolver, 3 buffers and 1 PeriodicWave. With `useReverb:0` there is no convolver and 35 gains, but the reverb buffer is still generated.
- **Methods.** All are instance-own arrow functions (`WebAudioTinySynth.prototype` has only `constructor`). Documented in README:

  Undocumented but reachable: `ready/0` (mentioned in prose), `init/0` and `loadMIDIfromSrc/0`, plus the private methods `_createWave _limitVoices _note _pruneNote _releaseNote _setParamTarget _tsConv`.
- **Members the tests rely on:** `_note` (harness wrapper), `notetab`, `playTime`, `song`, `program`, `loopEnd`, and `getAudioContext`. The #10 issue snippet also reads `playing`.
- **Properties** (`properties` block default → value after construction): `masterVol` 0.5, `reverbLev` 0.3, `quality` 1, `debug` 0, `src` null, `loop` 0, `loopEnd` 0, `internalcontext` 1, `tsmode` 0, `voices` 64, `useReverb` 1. The `observer` names are vestigial because nothing invokes them. - **Detached methods** (`const {noteOn,…} = synth`). Called unbound, all of these worked: `noteOn(0,60,100)` (notetab +1), `noteOff`, `send([0x91,64,90])`, `setProgram`, `setMasterVol`, `setQuality(0)`, `getTimbreName(1,35)`, `loadMIDI`/`playMIDI`/`getPlayStatus`/`stopMIDI` and `setTimbre`. `ready()` resolves after 200 ms of mock time.

### Questions for the supervisor (facts recorded, nothing decided)

1. **Q1 Harmonics.** Consumer element 0 is harmonic 1, while Web Audio and `_createWave` use index 0 for DC. Which open questions need a decision:
   - imag (sine phase, as `_createWave` uses) versus real placement
   - whether u16 is a raw relative amplitude or /10000 fixed-point
   - unsigned values cannot express sign or phase, so alternating-sign series such as a triangle cannot be written
   - 64 harmonics need a 65-coefficient engine limit
2. **Q2 Samples.** The i8→float map is ambiguous:
   - x/128 gives −1..0.9922
   - x/127 gives −1.0079..1
   - the affine map gives −1..1 but sends 0 to 0.0039

   The consumer's "exact sample-and-hold" promise also conflicts with #26's tolerance-based contract (buffer playback interpolates).
3. **Q3 Filter Q.** The consumer's 0.1..30 is unitless, but Web Audio lowpass/highpass Q is in dB and bandpass Q is linear. Choose linear Q with a documented conversion, or per-type native values.
4. **Q4 Key-tracked cutoff.**
   - Basis: note frequency with tuning, or operator frequency `note·t+f`.
   - 16× exceeds 22,050 Hz for notes ≥ 89 at 44.1 kHz.
   - A fixed 20 kHz cutoff exceeds Nyquist below 40 kHz.
   - A clamp policy is needed.
5. **Q5 Reverb percent.** `reverbLev = reverb/100` is implied, but `setReverbLev` applies ×8 (100% → wet gain 8.0, 3.3× the default). "0 = off" could mean `setReverbLev(0)` (convolver kept) or `useReverb:0` (constructor-only, no convolver).
6. **Q6 Master volume percent.** `masterVol = master_vol/100` is implied; full scale 1.0 is twice the engine default.
7. **Q7 Modulator frequency basis.** The Cairo doc gives `note_frequency·ratio+offset_hz` for every operator, but the engine uses the target operator's frequency for FM/AM operators (measured 2,645 Hz versus 1,325 Hz).
8. **Q8 Operator-0 lifetime rules.** Melodic voices end at note-off + 3.5·r[0], whatever the other operators' release. Drums stop at note-on + 3.5·d[0] and ignore note-off, release and sustain, so a drum with d[0]=0 is silent. The Cairo doc describes release per operator.
9. **Q9 Drum slots** 35..81 match the engine's 47-entry drummap. Drum timbres sound only on rhythm channels (channel 10 unless GS SysEx changes it). Confirm this stays the contract.
10. **Q10 Voices** pruning differs from "oldest note is cut": released notes are pruned first, and drum hits prune melodic voices to `voices−1`.
11. **Q11 Built-in coverage.** With d/r capped at 10, 32 built-in timbres cannot be re-expressed through the schema. Decide whether that matters.
12. **Q12 Routes.** Routes 9–10 are unreachable with ≤ 8 operators. A target must be an earlier operator, or note-on throws.
13. **Q13 Determinism.** The consumer's consistency claim fails at baseline for any sound with reverb > 0 (the default is 30), not just noise waveforms: the reverb impulse and n0/n1 are `Math.random` per `setAudioContext`. This depends on the #7 seed policy.
14. **Q14 Quality type.** The page must pass a Number: `setQuality("0")` selects quality 1.
15. **Q15 setTimbre references.** `setTimbre` keeps and mutates the caller's arrays, so the page should pass fresh objects (relevant to the #13/#26 copy semantics).
16. **Q16 Startup.** The constructor eagerly creates an AudioContext and plays a warm-up note, which affects the consumer's tap-to-start page (#12).

## 9. Other findings and risks (facts, no decisions)

- **Environment.** Chromium cannot run on this host without the extracted libraries. The smoke result depends on `LD_LIBRARY_PATH` pointing at scratch debs.
- **Tests and probes see no audio.** The tests and probes use the mock WebAudio, which records calls but renders nothing, so no listening or rendered-audio check was done. The noise and reverb buffer contents are not part of the traces, so `Math.random` does not affect `npm test`.
- **#4 memory.** In the #4 hang, the parser pushes millions of events per 150 ms. In a real tab, memory would grow until the tab is killed.
- **#6 failure mode.** Zero PPQ and the truncated header do not hang. They leave stuck or silent state: perpetual `play:1`, or a song with NaN timebase that replaces the previous one.
- **Unknown `w…` names.** An unknown name throws inside `_note` after the oscillator is created. No voice is recorded, but the oscillator is orphaned.
- **Missing upstream reference.** With `TINYSYNTH_REFERENCE` pointing at a missing file, the harness gives an uncaught stack trace rather than its descriptive failure.
- **Packaging.** Packaging leaks `test-midi/README.md` and would include any committed `docs/` tree; this is for T1/T9.
- **Hash stability.** `min.js` byte parity depends on terser 5.51.2. Package resolution was identical today, but there is no committed lockfile, so a future `^5.14.0` resolution could change the bytes (#5).
