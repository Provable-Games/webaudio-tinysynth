## 2. Parser contract as implemented

`loadMIDI(data)` reads `new Uint8Array(data)` into a local song (`{copyright, text, tempo:120, timebase, ev}`) and a local `maxTick`, and touches the synth only after the whole file has been read.

**Errors (D-013).** A failure throws an `Error` (`name` `"Error"`) with:
- `code`: one of the five codes below;
- `offset`: the absolute byte offset of the offending field, chunk or event (always present);
- `track`: the 0-based index of the track (MTrk) chunk being read or looked for. It is present from the first track chunk on and absent for header errors. Unknown chunks are not counted, so for files without unknown chunks it equals the legacy loop index;
- `message`: `"<code>: <description> (track <t>, byte <offset>)"`, or `"(byte <offset>)"` for header errors. The descriptions are short since the review fix batch (R3), for example `SMF_MALFORMED: VLQ over 4 bytes (track 0, byte 22)`, `SMF_TRUNCATED: event past chunk end (track 0, byte 62)`, `SMF_TRUNCATED: chunk past file end (track 0, byte 14)`, `SMF_TRUNCATED: no track 1 of 2 (track 1, byte 65)`, `SMF_MALFORMED: no running status`, `bad data byte`, `bad tempo`, `bad status 0xf8`, `End-of-Track length 1`, `no End-of-Track`, `SMF_UNSUPPORTED_DIVISION: SMPTE division 0xe728 (byte 12)`, `SMF_UNSUPPORTED_FORMAT: format 2 (byte 8)`, `SMF_INVALID_HEADER: no MThd header (byte 0)`.

| Code | Raised when | offset |
| --- | --- | --- |
| `SMF_INVALID_HEADER` | The first 4 bytes are not `MThd`, including inputs shorter than 4 bytes; or the header length is below 6 | 0; 4 for the length |
| `SMF_TRUNCATED` | The file ends inside the header chunk (fewer than 8 bytes, or fewer than 8 + header length) | 0 |
| | The file ends before a declared track chunk's 8-byte header ("file ends before track t of n") | where the chunk should start |
| | A chunk's declared length runs past the end of the file. This is checked for every chunk read, including skipped unknown chunks | the chunk start |
| | A delta-time or length VLQ, an event, a channel message, a meta event or a SysEx event runs past the end of its chunk | the VLQ start, or the event start (its status byte, or first data byte under running status) |
| `SMF_UNSUPPORTED_FORMAT` | The format is not 0 or 1 (2, or any unknown value) | 8 |
| `SMF_UNSUPPORTED_DIVISION` | The division has its high bit set (SMPTE, the message says "SMPTE division 0x..."), or it is 0 | 12 |
| `SMF_MALFORMED` | A VLQ longer than 4 bytes | the VLQ start |
| | A data byte where an event starts, with no running status (track start, or after a meta or SysEx event) | that byte |
| | A byte of 0x80 or more inside a channel message | that byte |
| | A status byte 0xF1 to 0xF6 or 0xF8 to 0xFE | that byte |
| | A tempo meta event whose length is not 3, or whose value is 0 | the event start |
| | An End-of-Track with a nonzero length | the event start |
| | A track chunk that ends without End-of-Track and is followed by anything other than the end of the file or an MTrk chunk ("no End-of-Track", review F5) | the chunk end |

Checks run in this order: magic, header length, header truncation, format, division, then chunks in file order.

**Structure.**
- Header and chunk lengths are read unsigned. A header longer than 6 bytes is accepted and its extra bytes are skipped.
- Formats 0 and 1 are supported. As before, `ntrks` is not checked against the format: format 0 with several tracks and `ntrks` 0 still load.
- Chunks are read until `ntrks` track chunks have been read. Chunks with another id are skipped and do not count. Bytes after the last needed chunk are ignored, as before.
- Every chunk read must fit in the file. Inside a track chunk, every read is bounded by the chunk end, so it is also bounded by the file end. Nothing is allocated from a declared length: memory grows only with the bytes actually present.
- VLQs are at most 4 bytes.
- Running status is per track. It starts unset in each track and is cancelled by meta and SysEx events. The legacy file-wide initial `0x90` is gone.
- Channel messages take 1 data byte (0xC0, 0xD0) or 2. SysEx (`F0`) and escape (`F7`) events become `[0xf0, ...data]`, as before. The tempo meta event (3 bytes, nonzero) becomes `[0xff51, 60000000/us]`, keeping fractional tempo. Copyright metas (0x02) are appended to `song.copyright`. Text metas 0x01, 0x03, 0x04 and 0x09 set `song.text`, and the last one wins. All other metas are skipped by their length. Text is decoded in 8,192-byte `String.fromCharCode.apply` chunks, so long texts cannot overflow `apply` and stay fast (review F2). Channel-event arrays are built as literals (review F3).
- End-of-Track ends the track, and any bytes after it in the chunk are skipped. The track's end tick includes the End-of-Track delta-time. `maxTick` is the largest track end tick.
- **Missing End-of-Track (documented recovery).** A track chunk without End-of-Track is accepted when it ends exactly after a complete event **and** the file ends there or an MTrk chunk follows (the second condition since review F5). That track then ends at its last event's tick, and an empty chunk ends at tick 0. The next track is read from its own chunk, so a missing end marker cannot bleed into it. If the chunk ends inside a delta-time or an event, the load fails with `SMF_TRUNCATED`; if anything else follows it (trailing bytes, an alien chunk, the rest of a track whose length was understated), with `SMF_MALFORMED` "no End-of-Track" at the chunk end.

**Install (unchanged effects).** After full validation, events are stable-sorted by tick as before. Then the legacy sequence runs: `stopMIDI()`, `notetab.length=0` (only if at least one track chunk was read), set `maxTick` and `song`, `reset()`, `locateMIDI(0)`. The WebAudio call traces of loads that replace a playing song are identical to the baseline's (parity test). A failed load makes no WebAudio call. It leaves `song` (the same object), `maxTick`, `playTick`, `playIndex`, `playing`, `playTime`, `tick2Time`, the channel arrays, the tuning and the timbre tables (`program`, `drummap`, including custom timbres) unchanged, and the song keeps playing.
