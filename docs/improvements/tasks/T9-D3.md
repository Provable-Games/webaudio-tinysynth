## 4. Vacuity

Run in Chromium with the new spec and `e4e32a7`'s three pages (`logs/vacuity-base-chromium.log`, 475/497, 5 cases fail):

- file switch: A first, the previous song plays (`play` 1, `maxTick` 960); B first, B plays by itself (`play` 1, `maxTick` 1440), with and without a previous song (5 checks fail);
- metadata: no titles, jstest without a charset, no fork links, `rel` missing, the About typos, the overflow (table right edge 1076 px against 1020 px), the Patch field not read-only, implicit globals `synth` (jstest) and `p,oscs,ids,id` (soundedit), and `console.log(synth)` (jstest);
- pedal: the old channel's sustain ends on a channel change, on unchecking, and on a MIDI pedal-up (`held` empty).

The iOS case passes on the base pages, as expected (they already retry on `click`). It was shown not to be vacuous with a mutation: with `"click"` removed from each page's start-event list the three cases fail, the refusal stays shown after the click and the context stays `suspended` (`logs/vacuity-ios-mutation-chromium.log`, 488/497).

## 5. Engine findings (reported, not changed)

- Creating a lazy context calls `send()` (`setAudioContext()`), and `send()` calls `context.resume()` through `_wake()`. In an iOS-style browser that first resume is made on the `pointerdown` and refused (and swallowed), before `StartAudio`'s own `synth.resume()`. It does no harm here, but a lazy synth that keeps a song without creating its context would remove the extra call. No engine change is needed for #19.
